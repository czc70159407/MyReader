# M16 高亮锚点文本化（跨字号/跨排版精确复原）

- 状态：已完成（真机验收 4/4 通过 + `build` 全绿，2026-11-25）
- 优先级：P0（M15 字号功能的必要补完）
- 触发：M15 真机验收后用户报「字体高亮有问题」——垂直 EPUB 排版基准从固定 312×504pt 改为「视口宽 + 字号」后，M12 时代的归一化页面比例锚点（0..1 quad）全部失效，历史高亮系统性错位。

## 1. 目标与范围

### 目标

EPUB 高亮锚点从「归一化页面比例坐标」升级为「**章节 + 文本指纹**」，换字号 / 旋转 / 重排后按文本内容重新定位并重建 quad，高亮始终贴合原文。

### 非目标

- PDF/CBZ/XPS 高亮（固定版式，原生 annotation 不受影响，保持现状）
- epub 水平模式高亮（M12 已拍板不做自绘 overlay，保持）
- 书签锚点（已用 M11 Location 分量，跨排版可用，不改）
- 旧 v1 锚点的自动语义修复（无法修复——v1 只有比例坐标，无文本信息；降级策略见 §4）

## 2. 现状与根因

| 事实 | 位置 |
|---|---|
| 高亮锚点 = 归一化 quad JSON（相对页面宽高 0..1） | `AnnotationDraft.anchor` / `AnnotationAnchorCodec` |
| 渲染 = 按当前页归一化坐标直接绘制 | `MuPdfVerticalView` savedQuads/drawQuadPath |
| M15 前垂直布局固定 312×504pt → 比例坐标稳定 | M9 决策 |
| M15 后按「视口宽 + 字号」排版 → 比例坐标失效 | `MuPdfVerticalView` relayout |
| M12 已记录限制「归一化 quad 跨重排页级近似」并拍板不做 | docs/m12-plan.md |

## 3. 方案（锚点 v2）

### 3.1 锚点格式

`annotations.anchor` 存 JSON（TEXT 列，**无 Room schema 变更**，版本门禁同 `EpubProgressCodec`）：

```json
{"v":2,"ch":0,"pi":3,"q":"Chapter 1 paragraph 0: ...","pre":"...","post":"..."}
```

- `ch`/`pi`：重排前记录时的 `Location` 分量（章节 + 章内页）；
- `q`：选中文本（空格归一化）；
- `pre`/`post`：前后各 ≤20 字符上下文，用于重复文本消歧。

### 3.2 重建算法（渲染端）

1. `pageFromLocation(ch, pi)` 得基准页；**章内 ±N 页（N=2）顺序搜索**（重排后章内页号与实际内容有偏移）；
2. 目标页 `getTextStructure(page)` 取 chars + quads；
3. chars 拼接后查找 `q`（含 `pre`/`post` 消歧），命中区间 → quads 子集；
4. 归一化后绘制；
5. **全部失败 → 隐藏该高亮**（宁可缺不要错位），并在标注面板标注「位置已失效」。

### 3.3 已有能力（S0 已确认）

- `MuPDFCore.getTextStructure(page)`：字符级 quad + 字符码（M14，已真机验证）；
- `MuPDFCore.selectTextByChars`：字符区间选择（M14 真机验证）；
- `MuPDFCore.pageToLocation/pageFromLocation`：章节 + 章内页（M11 真机验证）；
- `MuPDFCore.selectText`：StructuredText.copy 取文本（M12）；
- **不可用**：`StructuredText.search`（fitz 1.28.2 JNI 崩溃，M12 S0 已证）——故用 Java 层字符串匹配。

### 5.1 S0 结论（2026-11-25 实测）

| 门禁 | 结论 |
|---|---|
| S0-1 文本可重建 | **通过**：`getTextStructure` 字符级 quad + codes（M14 已有）足够；**但发现 fitz 空白输出不稳定**——同一文档 EM10 下字符流无空格、EM6 下有空格（真机日志实证）→ **必须空白不敏感匹配**（指纹与页文本统一删除全部空白 squash 后比较，已落地） |
| S0-2 阅读顺序连续 | **通过**（M14 字符级选择已真机验证） |
| S0-3 章内搜索覆盖 | **通过**：无需 ±N 页搜索——按「当前页全量 v2 锚点 × 页文本匹配」遍历，重排后内容换页自动命中（实现比计划更简单） |
| S0-4 全链路 | **通过**：创建（v2 落库）→ 重构 → 回放 4 项真机通过 |

**实现中修复的 3 个关键缺陷**：
1. fork `getTextStructure` 页字符缓存不随 `layout()` 重排失效 → 重排后按旧排版文本匹配必失败（已在 `layout()` 内清空）；
2. 渲染端 v2 仍按 `a.page` 过滤 → 重排后内容换页即被过滤（已改为 v2 不限页码、按页文本命中）；
3. 重建时机早于异步 relayout 完成 → 引入 `layoutEpoch` 重排代次驱动高亮重算。

## 7. 风险

| 风险 | 应对 |
|---|---|
| 文本指纹在重复段落歧义 | pre/post 上下文消歧；仍歧义取最先命中（记录限制） |
| 跨页高亮被重排拆分 | 拆成多段 quad 绘制（同一锚点内多页匹配）；MVP 折中只取首页区间（记录限制） |
| 大文档逐页 walk 成本 | 仅对「当前页 ±2」做，翻页时按需重建；缓存 textStructure（M14 已有单页缓存） |
| 与 M12 已拍板「不做」冲突 | 本里程碑是决策变更（M15 触发），需在 AGENTS.md 更新决策记录 |

## 8. 已知限制（已拍板接受）

1. **旧 v1 锚点不迁移**：v1 只有比例坐标、无文本信息，无法重建 → 降级不绘制（用户可在标注面板删除）。**新标注全部走 v2**。
2. **quote 指纹来自 M14 选区文本**：`selectTextByChars` 的 text 存在「首字符偶发缺失 + 英文无空格」的 M14 遗留问题（如 "ragraph 2:MyReader"），因 v2 采用空白不敏感（squash）匹配，不影响定位；**标注面板摘录文字偶见缺空格**为该遗留的表现，另行修复。
3. **跨页高亮**：重排后内容跨页时各页各画命中段（同一颜色），不做跨页合并；页边界处可能视觉断开。
4. **重复文本歧义**：同一页文本完全重复时取首个命中（pre/post 上下文已大幅降低概率）。
5. 固定版式（PDF/CBZ/XPS）高亮仍为 v1 归一化 quad（无重排，不受影响）。
