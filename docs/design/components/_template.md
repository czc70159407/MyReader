# 组件/页面条目模板

> 新增或改写任何条目时复制本模板。**未填满必填字段的条目不得进入开发**（评审直接退回）。

```markdown
# {区域} · {条目名}

- 状态：设计中 | 评审通过 | 已实现 | 已验收
- 优先级：P0 | P1 | P2
- 关联决策：D1~D8（无则写 —）
- 里程碑：M10 / 无
- 代码落点：file:path（可多个）
- 相关测试：file:path（无则写"待补：{测试类型}"）

## 1. 目标与入口
（用户要完成什么；从哪个页面/手势/按钮进入；失败或取消后回到哪里）

## 2. 布局
（ASCII 线框 + 尺寸引用 tokens.md 的 space-*；标注滚动容器与固定区）

## 3. 状态矩阵（必填）
| 状态 | 触发条件 | 展示 | 可执行动作 |
|---|---|---|---|
| 加载 | | | |
| 空 | | | |
| 错误 | | | |
| 成功 | | | |
| 禁用 | | | |
| 进行中 | | | |

## 4. 交互细则（必填）
- 点击 / 长按 / 双击：
- 返回键与其他系统手势：
- 与滚动/翻页手势的冲突及优先级：
- 重复点击与并发保护：
- 数据变化时的视觉复位（如列表重排）：

## 5. 文案
（引用 copy.md 的键名，不在此重写正文）

## 6. 表单校验（含输入时）
| 字段 | 规则 | 时机 | 反馈 | 业务层兜底 |

## 7. 无障碍
- 触达尺寸：
- 读屏语义（整块朗读内容）：
- 非长按替代路径：
- 焦点顺序与初始焦点：
- 颜色之外的信息载体：

## 8. 响应式
| 宽度/场景 | 变化 |

## 9. 验收场景（可执行）
1. 前置条件 → 操作 → 预期（逐条，含失败与边界）

## 10. 未决问题
（无则写"无"；有则标注责任人与阻塞范围）
```

## 填写规范

1. **状态矩阵缺行**：加载/空/错误三态必须全部出现，即使结论是"不适用"，也要写明原因。
2. **验收场景必须可复现**：写清前置数据（如"库内已有 1 个加密 PDF"），不写"测试导入功能正常"。
3. **文案不重复**：正文只在 `copy.md` 维护，条目内只写键名，避免两处漂移。
4. **代码落点必须真实存在**：新文件写计划路径，并在实现后回填。
5. **决策引用**：凡涉及 D1~D8 的结论，必须在条目中标注引用，避免实现时再次讨论。
